# Delivery Guidelines

- Use consistent feature naming across repos when one feature spans multiple repositories.
- Keep artifact language human-readable first, implementation-aware second.
- Store long-term memory as durable guidance, not raw transcripts.
- Treat synced MCP data as supporting context, not as the only source of truth.
- Use board overrides sparingly and keep them auditable.
- Include explicit test cases or acceptance scenarios during specification.
- Treat test planning as part of implementation planning, not a separate afterthought.
- Use sub-agents only for workstreams that are clearly parallelizable and have merge checkpoints.
